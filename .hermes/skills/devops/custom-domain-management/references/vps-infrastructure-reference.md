# VPS Infrastructure Reference

## Core Network Layout
- Hetzner Helsinki VPS @ 147.79.18.32
- eth0 MTU: 1400 (provider-enforced)
- Docker bridge default: 1500 → mismatch causes TLS/Postgres/SMTP hangs
- Fix: Custom network with `driver_opts { mtu: "1400" }`

## Docker Networks
1. `web` (external bridge) - Shared with Caddy
   - Contains: Caddy container
2. `<app>_<app>-net` (private bridge) - Per-app MTU 1400
   - Contains: postgres, api, web containers for that app

## Caddy Configuration
- Main file: `/etc/caddy/Caddyfile`
- Site files: `/srv/caddy/sites/*.caddy` (bind-mounted into container)
- Example site block:
  ```
  syntra.terrybot.top {
      reverse_proxy syntra-web:80
  }
  ```
- Auto-fragment: `/srv/caddy/sites/syntra.auto.caddy` (generated by sync script)
  ```
  syntra.cyberslide.net {
      reverse_proxy syntra-web:80
  }
  ```

## Secrets Management
- File: `/srv/secrets/syntra.env`
- Loaded via `env_file:` in docker-compose
- Contains:
  - POSTGRES_PASSWORD
  - SESSION_SECRET (64+ chars random)
  - REPLIT_DOMAINS (comma-separated platform hostnames)
  - REPLIT_DEV_DOMAIN (fallback hostname)
  - SMTP credentials for contact form

## Deployment Flow
1. GitHub push → webhook (port 9000)
2. `project_dev.sh` script:
   - Pulls latest code
   - Runs `docker compose up -d --build`
   - Executes drizzle migrations
   - Reloads Caddy via `docker exec caddy caddy reload`
3. Caddy picks up new/changed site files automatically

## Verification Commands
```bash
# Check Caddy sites
docker exec caddy caddy adapt --config /etc/caddy/Caddyfile --adapter caddyfile

# Check container networks
docker network inspect syntra_syntra-net

# Check MTU on custom network
docker network inspect syntra_syntra-net | grep -i mtu

# Verify cert issuance
docker exec caddy ls /data/caddy/certificates/acme-v02.api.letsencrypt.org-directory/

# Check webhook logs
tail -f /var/log/webhook.log
```
