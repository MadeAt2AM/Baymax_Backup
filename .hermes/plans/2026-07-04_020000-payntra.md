## 1. Goals & Non-Goals

**Goal:** Ship a full-stack monthly expense ledger replacing the physical notebook workflow (see PRD HTML prototype). Core problem: *"What do I need to clear out of my account right now when my salary hits?"* — every month starts as a clone of the prior month's baseline items, all `PENDING`, then mutated in place.

**Non-goals (v1):**
- Multi-user / family / shared ledgers (single-user per account)
- Bank integrations / OCR receipt scanning
- Multi-currency (single currency assumed)
- Mobile native app (responsive web only)
- Reporting / charts / analytics (just the operational dashboard)
- Email reminders

| Auth | Hand-rolled JWT in HTTPOnly cookies + bcrypt (10 rounds) | PRD-literal. JWT in cookie so SPA works without bearer-token plumbing |
| Mail | `nodemailer` with SMTP creds from `~/.hermes/.env` | Already configured (EMAIL_SMTP_HOST etc.) |

| Tests | Vitest (unit) + Playwright (E2E happy path) | Vite-native, fast |
| Deploy | Docker Compose on dev VPS, behind Caddy | Standard MadeAt2AM pattern, webhook auto-redeploy |

**No `any` policy:** every API response is typed via `z.infer<typeof Schema>`. Backend uses `tsc --strict` with `noUncheckedIndexedAccess: true`. Client `tsconfig.json` mirrors.

## 4. Database Schema (PRD-literal, verbatim)

From PRD §3, deployed via `db/init.sql` on first `docker compose up`:

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  reset_secret VARCHAR(255) DEFAULT NULL,
  reset_secret_created_at TIMESTAMP WITH TIME ZONE DEFAULT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE expense_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(100) NOT NULL,
  default_amount NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE monthly_ledgers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  month_year VARCHAR(7) NOT NULL,
  UNIQUE(user_id, month_year)
);

CREATE TABLE ledger_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  ledger_id UUID REFERENCES monthly_ledgers(id) ON DELETE CASCADE,
  template_id UUID REFERENCES expense_templates(id) ON DELETE SET NULL,
  name VARCHAR(100) NOT NULL,
  amount NUMERIC(12, 2) NOT NULL DEFAULT 0.00,
  status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
  notes TEXT DEFAULT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT status_chk CHECK (status IN ('PENDING', 'PAID'))
);

CREATE INDEX idx_ledgers_user_date ON monthly_ledgers(user_id, month_year);
CREATE INDEX idx_ledger_items_lookup ON ledger_items(ledger_id);
```

## 5. The Rollover Engine (the heart of the app)

Lives in `server/src/services/rollover.ts`. Triggered on every `GET /api/ledger/:monthYear` when the requested month has no row.

**Algorithm (PRD §1, step-by-step):**

1. Compute `target = "YYYY-MM"` from request param
2. `SELECT id FROM monthly_ledgers WHERE user_id = $1 AND month_year = $2`
3. **Path A — exists:** `SELECT * FROM ledger_items WHERE ledger_id = $id ORDER BY created_at` → return
4. **Path B — absent (initialization):**
   a. Compute `prior` = target − 1 month, **safely crossing year boundaries** (`2026-01` → `2025-12`)
   b. `SELECT ledger_items.* FROM ledger_items JOIN monthly_ledgers ON ... WHERE month_year = $prior AND user_id = $1`
   c. **If prior month has rows:** `INSERT INTO monthly_ledgers` then bulk `INSERT INTO ledger_items` cloning every row, **status forced to 'PENDING'**, notes kept verbatim
   d. **Else (no prior at all — first-ever month):** `SELECT * FROM expense_templates WHERE user_id = $1 AND is_active = TRUE` → bulk-insert each as a ledger_item with `template_id` set, status='PENDING', amount=`default_amount`, notes=NULL
   e. Return the freshly-created ledger_items

**Concurrency:** wrap Path B in a single transaction with `SELECT ... FOR UPDATE` on the `monthly_ledgers` row insertion. If two requests race, the second sees the row and falls into Path A.

**Year-boundary math:** use `new Date(target + '-01T00:00:00Z')`, set to day 0 → `toISOString().slice(0,7)`. Test cases: `2026-01` → `2025-12`, `2026-03` → `2026-02`, `2027-01` → `2026-12`.

## 6. REST API Contract (PRD §2 — full endpoint matrix)

| Method | Endpoint | Purpose | Response codes |
|---|---|---|---|
| POST | `/api/auth/login` | `{email, password}` → sets `payntra_token` HTTPOnly cookie | 200, 401 |
| POST | `/api/auth/logout` | clears cookie, no-op server-side | 200 |
| POST | `/api/auth/forgot-password` | `{email}` → always 200, generates `reset_secret` if user exists, sends SMTP | 200, 500 |
| POST | `/api/auth/reset-password` | `{secret, newPassword}` → validates `NOW() - reset_secret_created_at < 5min` | 200, 410 Gone, 400 |
| GET | `/api/profile` | returns current user (id, email, created_at) | 200, 401 |
| PUT | `/api/profile/password` | `{currentPassword, newPassword}` → no email, revokes all sessions (clears reset_secret, rotates JWT) | 200, 403 |
| GET | `/api/ledger/:monthYear` | Triggers rollover if needed, returns ledger + items | 200, 201 |
| PATCH | `/api/ledger/items/:id` | `{status?, notes?, amount?}` partial update, optimistic | 200, 404 |
| GET | `/api/templates` | List active + inactive templates | 200 |
| POST | `/api/templates` | `{name, defaultAmount, isActive?}` | 201 |
| PATCH | `/api/templates/:id` | partial update | 200, 404 |
| DELETE | `/api/templates/:id` | soft-delete (`is_active = false`) | 204 |

All routes (except `login`, `forgot-password`, `reset-password`) require valid `payntra_token` HTTPOnly cookie. Auth middleware parses JWT, attaches `request.user`.

## 13. Verification Protocol (Karpathy guidelines)

For every phase:
1. **Unit tests green ≠ done.** Always end-to-end verify the live URL.
2. **For each backend change:** push, wait for webhook (≤60s), `project.sh status` shows new container, `curl` the affected endpoint from outside.
3. **For each frontend change:** visual + functional check in browser, dark + light mode, mobile + desktop.
4. **For the rollover engine specifically:** run the unit tests, then create a test user, seed a `2026-06` ledger via direct DB, hit `/api/ledger/2026-07` and confirm cloning worked.
5. **Rollback path:** `project.sh teardown payntra` removes container + DNS (preserves files). Git revert + push restores the last good commit.
